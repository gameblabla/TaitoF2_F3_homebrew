System Information:
    4 scrolling layers (512x512 or 1024x512) of 4/5/6 bpp tiles.
    1 scrolling text layer (512x512, characters generated in vram), 4bpp chars.
    1 scrolling pixel layer (512x256 pixels generated in pivot ram), 4bpp pixels.
    2 sprite banks (for double buffering of sprites)
    Sprites can be 4, 5 or 6 bpp
    Sprite scaling.
    Rowscroll on all playfields
    Line by line zoom on all playfields
    Column scroll on all playfields
    Line by line sprite and playfield priority mixing

    All special effects are controlled by an area in 'line ram'.  Typically
    there are 256 values, one for each line of the screen (including clipped
    lines at the top of the screen).  For example, at 0x8000 in lineram,
    there are 4 sets of 256 values (one for each playfield) and each value
    is the scale control for that line in the destination bitmap (screen).
    Therefore each line can have a different zoom value for special effects.

    This also applies to playfield priority, rowscroll, column scroll, sprite
    priority and VRAM/pivot layers.

    However - at the start of line ram there are also sets of 256 values
    controlling each effect - effects can be selectively applied to individual
    playfields or only certain lines out of the 256 can be active - in which
    case the last allowed value can be latched (typically used so a game can
    use one zoom or row value over the whole playfield).

    The programmers of some of these games made strange use of flipscreen -
    some games have all their graphics flipped in ROM, and use the flipscreen
    bit to display them correctly!.

    Most games display 232 scanlines, but some use lineram effects to clip
    themselves to 224 or less.

Graphics:
	Palette:
		Palette is stored as a 4 byte value ($00RRGGBB). Upper byte may be related to alpha?
		Are the lower 2 bits of each color ignored?
		Palette ram has room for 128 64 color palettes.

	Text characters:
		256 characters.
		8 x 8 4 bit characters. Each character is 32 bytes long.
		They are stored 2 pixels per byte, 4 sequential bits define a pixel
		(00001111 22223333 - binary layout of 4 pixels 3,2,1,0).
		Each 2 pixel group is stored right to left, and the pixels are stored in a byte right to left.

	Tile characters:
		16384 characters.
		16 x 16 4-6 bit characters. Each character is 128 bytes long.
		Characters are stored 2 pixels per byte (1 nibble per pixel, right pixel first), The 2 pixels groups
		are stored left to right, The upper two bits are stored interleaved. The first byte is the lower bit of the first 8
		pixels, followed by the upper bit of the first 8 pixels.

	Sprite characters:
		16384 characters.
		16 x 16 4-6 bit characters. Each character is 128 bytes long.
		(11110000 33332222 55554444 77776666 - binary layout of 8 pixels (4 bit) 7,6,5,4,3,2,1,0).

Playfield tile info:
	$C000 0000 - X/Y Flip
	$3000 FFFF - Tile index
	$0DFF 0000 - Colour (top 2 bits use not clear, always set)
	$0200 0000 - Alpha blend mode

F3 sprite format:
	Word 0:	0xFFFF	Tile number (LSB)

	Word 1:	$FF00	X zoom
		$00FF	Y zoom

	Word 2:	$03FF	X position

	Word 3:	$03FF	Y position

	Word 4:	$8000	Add 16 to sprite x position
		$4000	If set use current x, if clear use saved x
		$2000	Add 16 to sprite y position
		$1000	If set use current y, if clear use saved y
		$0800	Sprite block start
		$0400	Use same colour on this sprite as block start
		$0200	Y flip
		$0100	X flip
		$00FF	Colour

	Word 5:	$FFFF	Tile number (MSB), probably only low bits used

	Word 6:	$8000	If set, jump to sprite location in low bits
			$03FF	Location to jump to.

	Word 7:	$FFFF	Unused?  Always zero?

	A blank entry is required between sprite blocks. The format is:
	dc.l	$0000FFFF, $00000000, $00000000, $00000000

Roms (for Puzzle Bobble 3):
	68020 Code (32 bit data is interleaved across 4 roms):
		e29-12.rom - Bytes 1 of 4.
		e29-11.rom - Bytes 2 of 4.
		e29-10.rom - Bytes 3 of 4.
		e29-16.rom - Bytes 4 of 4.

	68000 Code (16 bit data is interleaved across 2 roms):
		e29-13.rom - Bytes 1 of 2.
		e29-14.rom - Bytes 2 of 2.

	Sprite Data (16 bit data is interleaved across 2 roms):
		e29-02.rom - Bytes 1 of 2.
		e29-01.rom - Bytes 2 of 2.

	Tile Data (4-6 bit data, stored same as sprites for lower 4 bits, with upper two bits stored in seperate rom):
		e29-08.rom - Bytes 1 of 2.
		e29-07.rom - Bytes 2 of 2.
		e29-06.rom - Upper 2 bits of each pixel packed 8 to a byte, planes split between
		two bytes.

	Sound Data (Each bank is stored in a rom, banks are 4MB, but do not have to be completely full):
		Bank 1 empty
		e29-03.rom - Bank 2 of 4, only uses 2MB.
		e29-04.rom - Bank 3 of 4, only uses 2MB.
		e29-05.rom - Bank 4 of 4, only uses 2MB.
